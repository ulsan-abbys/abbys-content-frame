# Codex로 네이버 글 한 편 준비하기

2026-11-14 D22: 글쓰기 엔진은 Codex 또는 Claude Code를 쓸 수 있지만, 네이버 작업의 실행 표준은 Codex입니다. 공개 발행은 사용자가 결정합니다. 기본 도착점은 임시저장입니다.

## 시작하기

Codex 앱 또는 CLI 설치 후 로그인하고 Git·uv를 준비하세요. 저장소를 받아 Codex에서 폴더를 연 뒤 [시작 프롬프트](../prompts/codex_시작.md) 전체를 한 번 붙여 넣으세요. 이후 명령은 Codex가 저장소 루트에서 실행합니다. 앱만 설치했다면 `write --engine codex`에 필요한 CLI 설치·로그인을 doctor 결과에 따라 준비해야 합니다. 로그인은 사용자가 직접 합니다.

| 단계 | 사용자가 할 일 | Codex가 할 일 / 멈출 곳 |
|---|---|---|
| 준비 | 필요한 도구를 설치하고 직접 로그인 | `uv run frame setup doctor`로 CLI·주제·키 유무 확인. 키 값을 출력하지 않음 |
| 주제 설정 | 분야·지역·독자·검색어·주당 글 수 답변 | 기존 답을 재사용하고 `uv run frame setup topics` 또는 `--from-json topics.json` 실행 |
| 후보 조사 | 선택적으로 RSS 출처·API 키 준비 | `uv run frame research --engine codex`로 후보 조사. N1은 RSS, N2는 NAVER API HUB 키가 있으면 실행. 키가 없으면 생략 |
| G1 주제 선택 | 후보 중 쓸 주제를 직접 선택 | 후보와 근거를 보여 주고 기다림. 조사 생략 시에도 주제를 임의 확정하지 않음 |
| 작업폴더 | 화자·말투 등 빠진 정보만 답변 | 폴더가 없을 때만 `uv run frame new my-blog --field "생활" --name "생활 기록자" --region "울산"` 실행. 값은 사용자 답으로 바꾸고 작업 프로필에 반영 |
| 초안·검사 | 필요한 추가 정보 제공 | `uv run frame write my-blog --topic "선택한 제목" --engine codex` 실행 후 출력된 경로로 `uv run frame check my-blog/초안/글.md --profile my-blog/profile.toml` 실행. 실패 수정·재검사 |
| G2 경험·사실 검수 | 실제 경험을 작성하고 사실·출처를 직접 확인 | 경험 슬롯과 확인할 내용을 보여 주고 기다림. 경험을 창작하지 않고 사람의 수정 후 다시 검사 |
| 게시 준비 | 사용할 브라우저 도구 연결·선택 | `uv run frame naver draft my-blog/초안/글.md`로 HTML과 `.agent.txt` 생성 |
| 임시저장 | 연결한 도구의 작업을 확인 | 아래 서버 절차 후 지시서를 실행하고 실제 저장 상태·제목·본문 확인 |
| G3 공개 발행 | 원할 때 해당 글·대상 블로그의 공개 발행을 명시 승인 | 승인 범위가 명확할 때만 발행. 이미 받은 승인은 재질문하지 않음. 실제 게시물 URL을 열어 검증 |

`글.md`는 예시입니다. 실제 명령 출력에 나온 파일명을 사용합니다. doctor는 CLI 존재를 점검하며 로그인 성공이나 구독 상태를 보장하지 않습니다. API 키는 선택 사항입니다. 설정 항목과 JSON 형식은 [API 키 발급 가이드](API_키_발급_가이드.md)를 참고하세요. 조사 실패나 근거 없는 후보를 성공으로 보고하지 않습니다.

## 로컬 준비물을 브라우저로 열기

전용 serve 명령은 없습니다. Codex는 별도 터미널에서 HTML이 생성된 **초안 폴더**로 이동해 서버를 실행합니다.

```powershell
cd my-blog/초안
python -m http.server 8770 --bind 127.0.0.1
```

Python 명령이 없으면 저장소의 uv 가상환경 Python을 사용합니다. Windows에서 위 폴더 기준 명령은 `../../.venv/Scripts/python.exe -m http.server 8770 --bind 127.0.0.1`입니다. 서버는 이 작업 중에만 유지하고 끝나면 Ctrl+C로 종료합니다.

브라우저 에이전트는 `file://` 주소를 열 수 없으므로 Codex가 생성된 `글.agent.txt`의 HTML 주소를 `http://127.0.0.1:8770/글.naver.html`로 바꿉니다. 파일명에 공백·한글이 있으면 URL 경로를 인코딩할 수 있습니다. 안전 지침과 확인 개수는 보존합니다. 서버 페이지가 실제로 열리는지 확인한 뒤 지시서를 따릅니다. 연결된 도구가 로컬 서버나 서식 있는 복사·붙여넣기를 지원하지 않으면 그 지점에서 인계하고, 사용자가 직접 붙여넣도록 안내합니다.

입력·저장·발행은 한 도구만 담당합니다. 특정 제품은 필수가 아닙니다. 사용자가 연결한 브라우저 도구의 실제 기능부터 확인합니다. [브라우저 작업 상세 지침](브라우저_에이전트에게_맡기기.md)의 서식·내용 대조와 중단 조건도 따릅니다.

## 멈춰야 하는 곳과 완료 기준

- G1의 주제 선택, G2의 실제 경험·사실 검수는 사용자 응답을 기다립니다. 기계 검사 통과는 사실 확인이나 공개 승인이 아닙니다.
- 기존 로그인 세션만 사용합니다. 로그인 화면·캡차·보호조치·명시적 사이트 차단에서는 즉시 중단합니다. 대신 로그인·자동 재시도·우회하지 않습니다. 비밀번호나 토큰을 채팅에 요청하지 않습니다.
- 경험 슬롯·확인 필요 문구·서식 불일치·불명확한 공개 대상이 남으면 발행하지 않습니다. CLI는 G3 승인을 스스로 만들지 않습니다. 생성된 `.agent.txt`도 승인서가 아닙니다.
- **임시저장 완료:** 저장 완료 표시와 임시저장 목록의 제목을 확인하고 편집기 제목·본문·출처 링크를 원고와 대조합니다. 편집기 URL과 확인 결과를 보고하고 공개 게시물 URL이 아님을 밝힙니다.
- **발행 완료:** 승인받은 대상 블로그의 실제 게시물 URL을 다시 열어 제목·본문·출처 링크를 확인하고 보고합니다. 클릭 시도나 테스트 통과만으로 성공을 선언하지 않습니다. 결과가 불명확하면 게시물 존재부터 확인하고 중복 클릭하지 않습니다.

브라우저 도구가 없으면 연결 방법 또는 직접 붙여넣기를 안내하고 실행 대기로 보고합니다. 기본 권장은 직접 붙여넣기이며, 브라우저 에이전트 이용에 따른 약관·계정 제재 위험은 사용자가 판단합니다. 저장소에는 네이버 로그인·게시·삽입 자동화 코드를 추가하지 않습니다.
