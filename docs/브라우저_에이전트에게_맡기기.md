# 브라우저 에이전트에게 초안 옮기기 맡기기

Claude in Chrome, ChatGPT @Chrome, Aside에서 사용자가 실행하는 절차입니다. 저장소(Claude/Codex)는 글쓰기·레이아웃과 로컬 HTML·실행 지시서를 만들며, 네이버 입력·임시저장 실행은 사용자가 고른 브라우저 에이전트가 맡습니다(owner 설계: 2026-11-13). 사용하는 도구가 로컬 파일 열기, 버튼 클릭, Ctrl+V와 편집기 서식 확인을 지원해야 합니다.

> **경고 — 기본 권장은 사람이 직접 붙여넣기입니다.**
> 네이버 이용약관은 자동화 수단에 의한 게시물·콘텐츠 삽입을 금지한다 — 실제 네이버 블로그에 에이전트로 붙여넣는 것은 계정 제재 위험이 있으며 사용자 본인의 판단이다.
> 이 문서는 네이버의 허용이나 계정 안전을 보장하지 않습니다. 게시 여부는 사용자가 결정하며, 승인한 글의 발행 조작은 브라우저 에이전트에 맡길 수 있습니다.

## 승인한 글은 발행 결과 확인까지 (2026-11-14 개정)

사용자가 대상 글·블로그의 공개 발행을 명시 승인했다면 임시저장에서 멈추지 않고 발행된 게시물 URL·제목·본문·출처 링크를 확인합니다. 이미 받은 승인을 반복해서 묻지 않습니다. 승인 없이 생성된 `.agent.txt`는 승인서가 아니며 기본 동작은 임시저장입니다. 연습용 `--editor-url` 지시서는 발행을 금지합니다.

미작성 경험 슬롯·확인 필요 문구·검증 실패가 남으면 발행하지 않습니다. 경험을 창작하지 않습니다. 로그인·보호조치·캡차·명시적 사이트 차단에서는 중단하며 우회하지 않습니다. 사용자가 선택하고 실제 연결된 브라우저 도구를 사용합니다. Claude와 Codex 모두 같은 절차를 따르며 Aside는 필수가 아닙니다. Codex의 Chrome/컴퓨터 제어도 연결·접근 가능 여부를 확인한 뒤 사용할 수 있습니다. Claude in Chrome의 실패를 다른 도구의 실패로 단정하지 않습니다.

같은 글의 입력·저장·발행 담당은 한 도구입니다. 병렬 작업은 조사·검수에 한정합니다. 발행 결과가 불명확하면 먼저 게시물 존재를 확인하고 중복 클릭하지 않습니다. 2026-11-13 실제 발행 성공은 Codex+Aside 조합 1건이며 다른 조합의 성공을 보장하지 않습니다.

먼저 `uv run frame naver draft 작업실/초안/글.md`를 실행합니다. 함께 생성된 `글.agent.txt` 전체를 그대로 복사해 실행 브라우저(Aside, ChatGPT @Chrome 등) 채팅창에 붙입니다. HTML의 절대 file URI와 확인 숫자가 이미 들어 있습니다. 지시서는 굵기 번짐·서식 불일치 시 저장 전 중단, 로그인 화면·캡차·보호조치·'과도한 접근' 시 즉시 중단과 화면 문구 보고, 한 번에 한 편만 실행, 임시저장함 제목 확인을 포함합니다. 경험 칸은 비워 둔 채 저장하고 사람이 채웁니다. 임시저장 확인 후 에이전트가 같은 글쓰기 화면에서 지시서에 포함된 읽기 전용 스크립트를 실행하고, 반환된 JSON 문자열 전체를 답변 마지막의 `json` 코드 블록으로 전달합니다. 실행할 수 없으면 ‘캡처 불가’와 이유를 보고합니다. 이미 로그인한 사용자 브라우저 프로필에서만 진행합니다. 새 프로필을 만들거나 로그인 정보를 전달하지 마세요.

## 수동으로 대상을 지정할 때 참고할 프롬프트

```text
초안 HTML: [여기에 .naver.html의 절대 경로]
대상 편집기: [사용자가 이미 열어 둔 편집기 탭]

사용자가 이미 로그인한 브라우저 프로필만 사용해 초안을 옮겨 줘.
CAPTCHA/캡차, 보호조치 또는 로그인 화면이 나오면 즉시 중단하고 알려 줘.
대신 로그인하거나 자동으로 재시도하지 마. 우회나 다른 프로필 사용도 금지야.

1. .naver.html을 열고 확인 줄의 제목·소제목·목록·굵게·링크 기대 개수를 기록해.
2. 페이지의 [본문 복사] 버튼을 클릭하고 복사 상태를 확인해.
3. 대상 편집기의 본문 칸을 클릭하고 키보드 Ctrl+V를 눌러.
4. 원본 HTML 페이지로 돌아가 [제목 복사]를 클릭하고 복사 상태를 확인해.
5. 편집기 제목 칸을 클릭하고 Ctrl+V를 눌러.

본문을 type/fill/텍스트 입력 도구로 타이핑하거나 HTML 소스를 입력하지 마.
서식 있는 클립보드는 페이지의 복사 버튼에서 만들어야 해.
Ctrl+A로 페이지 전체를 복사하면 안내 바까지 들어가므로 금지야.
복사 실패 또는 도구 기능 부족이면 중단하고 사람이 직접 붙여넣도록 알려 줘.
기존 제목이나 본문이 있으면 덮어쓰거나 중복 삽입하지 말고 중단해.

붙여넣은 편집기 본문에서 소제목(h2), 목록 항목(li, ul 개수가 아님),
굵게(strong/b), 링크(a)의 수를 확인 줄과 대조해.
제목 칸에는 제목 1개가 원문과 같고 본문에 제목이 중복되지 않는지도 확인해.
출처와 링크 주소, 문단 내용, 경험 슬롯도 원문과 대조해.
각 항목의 기대값/실제값을 보고해. 개수를 확인할 수 없거나 다르면 성공이라고
말하지 말고 임시저장도 하지 않은 채 중단해. 자동 재시도하지 마.

검증이 모두 맞으면 [임시저장]만 클릭하고 저장 완료 표시를 확인해.
완료 표시가 없으면 저장 성공이라고 말하지 마.
현재 사용자가 대상 글·블로그의 공개 발행을 명시 승인했고 사실·출처·경험·서식 검증을 마쳤다면 발행 설정을 확인하고 발행해. 미작성 경험 슬롯이나 확인 필요 문구가 남으면 발행하지 마. 승인이 없으면 임시저장으로 끝내. 발행 후 실제 게시물 URL을 열어 제목·본문·출처 링크를 확인하고 보고해. 결과가 불명확하면 게시물 존재부터 확인하고 중복 발행하지 마.
```

`확인` 줄의 목록은 목록 묶음이 아닌 항목 수입니다. 경험 슬롯의 굵게 표시도 굵게 개수에 포함합니다. 개수 일치는 서식 확인의 최소 조건이며 내용 검수나 게시 승인이 아닙니다.

## 임시저장 결과 점검

에이전트가 반환한 `json` 코드 블록 내용을 UTF-8 `capture.json`으로 저장하고 `frame naver check 원고.md capture.json`으로 점검합니다. 직접 수집할 때는 아래 절차를 사용합니다.

1. 사람이 임시저장함에서 글을 엽니다. 현재 글쓰기 화면에서도 점검할 수 있습니다.
2. 터미널에서 `frame naver capture-script`를 실행해 출력된 JavaScript를 복사합니다.
3. 글쓰기 화면에서 F12 → Console을 열고 스니펫을 붙여 실행합니다.
4. 클립보드의 JSON을 UTF-8 `capture.json` 파일로 저장합니다. 클립보드 복사가 지원되지 않으면 반환된 JSON 문자열을 복사해 저장합니다. 문자열을 한 번 더 감싼 JSON도 읽을 수 있습니다.
5. `frame naver check 원고.md capture.json`으로 제목·소제목·목록·굵게·링크·본문·누출·경험 칸을 점검합니다.

C4B는 소제목과 원고에서 전체가 굵은 블록을 제외한 본문의 과다 굵게를 점검하며, 없으면 PASS, 20% 이하면 WARN, 20%를 넘으면 FAIL입니다.

스니펫은 화면의 내용과 서식을 읽기만 하며, DOM 수정·클릭·저장·게시·네트워크 요청을 하지 않습니다. DevTools의 `copy`가 있으면 수집 JSON을 클립보드에 복사합니다. 로그인·보호조치·캡차에서는 중단하세요.

기본 `--stage draft`에서는 경험 칸이 남으면 WARN이며, `--stage publish`에서는 FAIL입니다. `--json`은 구조화된 판정 결과를 출력합니다. `--label`은 `naver draft`와 동일하게 경험 라벨을 지정하며, 생략하면 작업 폴더 설정 또는 `내 경험`을 사용합니다. 변환기의 실제 경험 칸 출력 문구를 기준으로 대조합니다.

종료 코드는 PASS·WARN 0, FAIL 1, 입력 오류 2입니다. 요약의 분자는 PASS 개수입니다. 이 검사는 수집 시점의 화면을 대조하며 실제 서버 저장 완료나 게시 승인을 보장하지 않습니다. 경험 칸이 지워진 경우 실제 작성 여부와 최종 발행은 사람이 확인합니다.
