# 새 모듈 만들기

사람과 AI가 함께 쓰는 기법 생성 안내입니다.
먼저 `README.md`, `AGENTS.md`, 관련 모듈 카드를 읽습니다.
아래에서 필요한 확장만 고릅니다. 모든 작업에 새 포트나 노드가 필요한 것은 아닙니다.

| 확장 | 바꿀 곳 | 검증 |
|---|---|---|
| 금칙어 규칙 | `config/rules/`, 프로필 | 허용·차단·오탐 사례 |
| 외부 도구 | `src/frame/adapters/`, 조립 코드 | 가짜 구현과 실패 응답 |
| 작업 흐름 | `config/graph.toml`, `modules/` | ID·연결·관문 불변 조건 |

**core는 adapters를 import하지 않습니다.** `frame.cli`도 가져오지 않습니다.
core에는 파일·네트워크·프로세스 I/O를 넣지 않습니다.
포트는 `core/ports.py`의 `typing.Protocol`입니다.
어댑터는 포트를 구현합니다. `cli.py`와 `config_loader.py`가 바깥에서 조립합니다.
런타임은 Python 3.11 이상과 표준 라이브러리만 사용합니다. 개발 의존성은 pytest입니다.

## (1) 규칙팩 추가

파일명은 `config/rules/education_ko.toml`처럼 정합니다.
팩 이름은 영문·숫자·밑줄·하이픈만 허용합니다.
각 규칙은 `[[rule]]` 테이블이며 아래 5개 문자열 필드를 씁니다.

| 필드 | 의미 | 예시 |
|---|---|---|
| `id` | 구별 가능한 규칙 ID | `education.guarantee` |
| `pattern` | Python 정규식 | `'합격\s*보장'` |
| `severity` | 실패 또는 경고 | `error`, `warn` |
| `reason` | 사용자에게 보여 줄 이유 | 결과 단정 여부 확인 |
| `ref` | 근거 또는 확인 상태 | `확인 필요` |

```toml
# 모임 검토용 초안입니다. 법률 위반을 판정하는 규칙이 아닙니다.
[[rule]]
id = "education.guarantee"
pattern = '합격\s*보장'
severity = "error"
reason = "합격 결과를 단정하는 표현인지 사람이 확인해 주세요."
ref = "확인 필요: 교육 업종 광고 기준"
```

작은따옴표는 정규식의 역슬래시를 보존합니다.
`error`가 발견되면 실패합니다. `warn`만 있으면 통과할 수 있습니다.
확인하지 못한 법 조항을 지어내지 않습니다.
본문 전체의 문맥을 이해하는 검사가 아니므로 오탐 사례도 남깁니다.

`config/profile.toml`의 기존 `[rules]`를 편집합니다. 같은 테이블을 중복 추가하지 않습니다.
업종에 맞지 않는 기존 팩은 검토 후 교체합니다.

```toml
[rules]
packs = ["general_ko", "education_ko"]
```

`tests/test_education_rules.py` 예시입니다. 위 팩 파일을 만든 뒤 실행합니다.

```python
import pytest

from frame.config_loader import load_pack
from frame.core.checks import find_violations


@pytest.mark.parametrize("text, blocked", [
    ("합격 보장", True),
    ("합격\t보장", True),
    ("학습 계획을 안내합니다.", False),
    ("", False),
])
def test_education_guarantee(text, blocked):
    findings = find_violations(text, [load_pack("education_ko")])
    assert bool(findings) is blocked
    if blocked:
        assert findings[0].rule_id == "education.guarantee"
        assert findings[0].severity == "error"
```

`합격 보장은 하지 않습니다`도 현재 패턴에 걸립니다.
이런 오탐은 사람 검토 대상으로 설명하거나 규칙을 개선하고 회귀 테스트를 넣습니다.

## (2) 포트를 구현하는 어댑터 추가

| 순서 | 작업 |
|---|---|
| (1) | `src/frame/core/ports.py`에서 맞는 포트를 고릅니다. |
| (2) | 인자·반환값·오류 처리 계약을 정합니다. |
| (3) | `src/frame/adapters/`에 구현을 둡니다. |
| (4) | `cli.py` 등 조립 경계에서 주입합니다. |
| (5) | 가짜 구현으로 호출부를 검증합니다. 실제 I/O도 가짜 응답으로 대체합니다. |

기존 포트는 `LLMWriter`, `VideoRenderer`, `UrlChecker`, `TrendSource`, `GateLog`입니다.
메서드 서명이 맞으면 Protocol을 명시적으로 상속하지 않아도 됩니다.
새 동작을 기존 포트로 표현할 수 없을 때만 core에 새 Protocol을 추가합니다.

최소 골격은 `src/frame/adapters/template_writer.py`에 둡니다.
실제 AI 호출 대신 전달 계약을 확인하는 연습용 구현입니다.

```python
class TemplateWriter:
    def write(self, prompt: str, workdir: str) -> str:
        if not prompt.strip():
            raise ValueError("작성 요청이 비어 있습니다.")
        return f"초안 요청: {prompt}"
```

`tests/test_template_writer.py`에서 구현과 CLI 주입을 함께 확인합니다.
`workdir` 전달과 빈 요청을 검사합니다. 외부 AI는 실행하지 않습니다.

```python
import pytest

from frame.adapters.template_writer import TemplateWriter
from frame.cli import main
from frame.core.ports import LLMWriter


class FakeWriter:
    def __init__(self):
        self.calls = []

    def write(self, prompt: str, workdir: str) -> str:
        self.calls.append((prompt, workdir))
        return "가짜 초안"


def test_template_writer():
    writer: LLMWriter = TemplateWriter()
    assert writer.write("주제 정리", ".") == "초안 요청: 주제 정리"
    with pytest.raises(ValueError, match="비어"):
        writer.write("  ", ".")


def test_cli_with_fake_writer(tmp_path, capsys):
    fake = FakeWriter()
    assert main(["write", str(tmp_path)], writer=fake) == 0
    assert fake.calls == [("STATE.md 보고 지금 하는 일을 이어서 해줘.", str(tmp_path))]
    assert "가짜 초안" in capsys.readouterr().out


def test_cli_reports_writer_failure(capsys):
    class FailingWriter:
        def write(self, prompt: str, workdir: str) -> str:
            raise RuntimeError("도구 응답 실패")

    assert main(["write", "."], writer=FailingWriter()) == 1
    assert "도구 응답 실패" in capsys.readouterr().out
```

실제 외부 호출 어댑터에는 시간 초과·실패 종료 코드·잘못된 응답 테스트도 추가합니다.
`monkeypatch`나 주입한 함수를 사용해 네트워크와 프로세스 실행을 대체합니다.
파일을 추가하는 것만으로 CLI 기본 구현이 바뀌지는 않습니다.
기본 구현 교체가 필요하면 조립 코드를 바꾸고 CLI 회귀 테스트도 갱신합니다.

## (3) 노드·관문과 모듈 카드 추가

`config/graph.toml`은 설계 데이터입니다. 노드를 추가해도 자동 실행되지 않습니다.
새 노드 `N9`와 관문 `G6`를 넣는 예시입니다.

```toml
[[nodes]]
id = "N9"
name = "출처 재확인"
mode = "auto"

[[gates]]
id = "G6"
name = "출처 재확인 승인"
start = "L0"
max = "L1"
why = "원문과 주장의 일치 여부를 사람이 확인합니다."

[[edges]]
source = "N4"
target = "N9"

[[edges]]
source = "N9"
target = "G6"

[[edges]]
source = "G6"
target = "N5"
```

이 예시에서는 기존 `N4 → N5` 연결을 위 경로로 교체합니다.
그대로 두면 새 관문을 우회하는 경로가 생깁니다.
ID는 노드·관문 전체에서 고유해야 합니다. 모든 연결의 양 끝이 정의되어야 합니다.
G3·G5의 시작과 최대 단계는 모두 `HUMAN_ONLY`를 유지합니다.
N6 실패 시 N5로 돌아가는 최대 2회 제한도 보존합니다.

`modules/N9-source-review.md`를 만듭니다. 기존 카드의 다음 항목을 채웁니다.
관문 책임도 카드에 설명합니다. 필요하면 `modules/G6-source-approval.md`로 나눕니다.

| 카드 항목 | 적을 내용 |
|---|---|
| 하는 일 | 원문과 주장 대조, G6 검토 책임 |
| 입력 | 초안과 출처 목록 |
| 출력 | 대조 결과와 확인 실패 목록 |
| 끝 기준 | 대조 결과를 사람이 검토함 |
| 실패 시 되돌아갈 곳 | N4에서 출처 보완 |
| 금지 | 출처 조작, 미확인 주장의 승인 |
| 지금 상태 | 설계만 있음 / 구현 중 / 구현됨 |
| 맡은 사람 | 담당자가 동의한 이름 또는 비워 둠 |

`tests/test_config.py`의 기존 개수 기대값도 실제 설계에 맞게 갱신합니다.
개수만 맞추지 말고 새 경로와 우회 경로 제거를 검사합니다.
중복 ID, 없는 연결 대상, G3·G5 완화 설정을 거부하는지도 테스트합니다.
`frame graph`로 출력과 카드를 직접 대조합니다.

## (4) 테스트 작성과 실행

| 변경 | 필요한 경계 조건 |
|---|---|
| 규칙팩 | 허용·차단·빈 문자열·공백 변형·오탐 |
| 어댑터 | 정상 응답·빈 입력·도구 실패·응답 형식 오류 |
| 그래프 | 새 경로·중복 ID·없는 대상·사람 전용 관문 |

저장소 루트에서 실행합니다.

```powershell
python -m pytest -q
```

가상환경이 있으면 `.\.venv\Scripts\python.exe -m pytest -q`를 사용합니다.
`tests/test_architecture.py`를 건너뛰거나 약화하지 않습니다.
실패한 테스트를 지우지 말고 원인을 고칩니다.

## (5) PR 열기

먼저 변경 동작과 이유, 관련 Issue·모듈, 검증 결과를 정리합니다.
[PR 템플릿](../.github/PULL_REQUEST_TEMPLATE.md)의 각 항목을 채웁니다.
사람이 변경 내용을 검토하고 허용한 뒤 fork·브랜치·커밋·푸시를 진행합니다.
GitHub에서 원본 저장소를 대상으로 PR을 엽니다.
원본 주소는 `https://github.com/ulsan-abbys/avis-content-frame`입니다.
`ulsan-abbys`은 운영자가 알려준 소유자 이름으로 바꿉니다.
AI는 승인 없이 원격 저장소를 만들거나 커밋·푸시하지 않습니다.

## PR 전에

- [ ] 바꾼 동작과 경계 조건을 테스트했다.
- [ ] `python -m pytest -q` 결과 요약을 적었다.
- [ ] core가 adapters·cli·I/O에 의존하지 않는다.
- [ ] 테스트에서 실제 네트워크나 외부 AI·영상 도구를 부르지 않는다.
- [ ] 설정·모듈 카드·README가 실제 구현과 일치한다.
- [ ] 사용자 문구는 한국어이며 파일은 UTF-8이다.
- [ ] 비밀·개인정보·실제 환자 정보가 없다.
- [ ] G3·G5는 `HUMAN_ONLY`이며 자동 게시·봇 탐지 우회가 없다.
- [ ] 검사 통과를 사람의 검수나 게시 승인으로 표시하지 않았다.
- [ ] PR 템플릿에 미검증 항목과 한계를 적었다.
