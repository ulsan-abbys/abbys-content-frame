# AI에게 맡기기

저장소 루트에서 Claude Code 또는 Codex에 아래 문장을 붙여 넣습니다.
처음에는 다음 공통 요청도 함께 전달합니다.

```text
README.md와 AGENTS.md를 먼저 읽어 줘. 기존 변경을 보존해 줘.
한국어로 짧게 설명하고 결과는 표로 보여 줘.
비밀과 개인정보를 쓰지 마. 커밋·푸시·게시·업로드는 하지 마.
사람의 경험과 관문 결정을 만들어 내지 마.
```

## (a) 설치

```text
README를 읽고 이 저장소를 내 PC(Windows)에 설치하고 `uv run frame graph`, `uv run frame check examples/clinic/초안/01_겨울철-가려움-보습.md`가 도는지 확인해 줘. 각 단계 결과를 보여 줘.
기존 config/profile.toml이 있으면 덮어쓰지 마.
```

| 하는 일 | 끝나고 확인할 것 |
|---|---|
| Python 3.11 이상 확인, 가상환경 설치 | 사용한 Python 경로와 설치 결과 |
| 그래프와 예시 점검 실행 | 명령, 종료 코드, 출력, 실패 이유 |

PowerShell 활성화가 막히면 `.\.venv\Scripts\python.exe -m frame graph`처럼 실행합니다.
작업 폴더는 저장소 루트여야 합니다.
현재 clinic 예시는 본문 923자입니다. 기본 기준 1200~1800자에서는 분량 오류로 실패합니다.
이 결과는 설치 실패와 구분합니다. 통과 예시는 `uv run frame check tests/fixtures/good.md`로 확인합니다.

## (b) 내 분야로 바꾸기

```text
나를 인터뷰해서 config/profile.toml을 내 분야(○○)로 만들고, 내 업종 금칙어 규칙팩 config/rules/<업종>_ko.toml 초안을 만들어 줘. 법 조항은 확인 못 하면 '확인 필요'로 표시해.
.claude/skills/frame-customize/SKILL.md를 읽고 따라 줘.
질문은 최대 5개로 해 줘. <업종>은 education 같은 영문 식별자로 바꿔 줘.
기존 설정과 바뀐 설정을 비교하고, 새 규칙으로 예시 초안을 점검해 줘.
```

| 하는 일 | 끝나고 확인할 것 |
|---|---|
| 분야·독자·말투·분량 인터뷰 | 답하지 않은 내용을 사실처럼 채우지 않았는지 |
| 프로필과 규칙팩 작성 | `rules.packs`에 새 파일명에서 `.toml`을 뺀 값이 있는지 |
| 예시 초안 점검 | 오류·경고, 미확인 근거, 사람이 채울 경험 슬롯 |

팩 이름은 영문·숫자·밑줄·하이픈만 허용합니다. 한글 파일명은 로더가 거부합니다.
`persona`와 `style`은 AI가 읽고 적용합니다. 현재 `uv run frame write`가 자동으로 전달하지 않습니다.

## (c) 서브에이전트로 나눠 맡기기

```text
내 분야와 독자, 이번 글 주제, 내가 제공한 예전 글 3편을 먼저 확인해 줘.
자료가 없으면 필요한 경로나 내용을 물어봐 줘.
메인 에이전트가 다음 3개 서브에이전트에 병렬로 맡겨 줘.
(1) 주제 후보 조사: 독자의 질문과 후보 3개를 정리.
(2) 출처 수집·링크 확인: 공식 원문, 주장, URL, 확인 결과를 정리.
(3) 내 예전 글 3편에서 문체 요약: 말투·문장 길이·구성을 근거와 함께 정리.
각 에이전트는 읽기와 조사만 하고 공유 파일을 수정하지 마.
메인이 결과를 후보 | 독자 질문 | 출처·링크 상태 | 문체 근거 | 확인 필요 표로 합쳐 줘.
결과 한 건은 원문과 직접 대조. 대조한 원문 위치와 일치 여부도 적어 줘.
링크에 접근하지 못하면 확인 실패로 표시해. 출처와 예전 글을 만들어 내지 마.
병렬 도구가 없으면 그 한계를 먼저 알리고 같은 역할을 순서대로 수행해 줘.
```

| 하는 일 | 끝나고 확인할 것 |
|---|---|
| 조사 역할 3개 분담 후 병합 | 중복·상충 결과가 정리되었는지 |
| 원문과 직접 대조 | 최소 한 건의 원문 위치와 대조 결과가 있는지 |

## (d) 초안 → 점검 → 고치기 루프

```text
examples처럼 초안을 쓰고 `uv run frame check`가 통과할 때까지 최대 2번 고쳐. 그래도 실패하면 멈추고 이유를 보여 줘.
내 주제와 config/profile.toml을 사용하고 drafts/01_내-주제.md에 저장해 줘.
처음 점검한 뒤 수정은 최대 2회, 점검은 총 최대 3회로 제한해 줘.
실행마다 명령·종료 코드·오류·경고·수정 내용을 표로 보여 줘.
통과하려고 기준이나 규칙을 낮추거나 본문을 출처 아래로 옮기지 마.
경험 슬롯은 비워 두고 내가 채울 항목을 알려 줘. 출처를 지어내지 마.
```

| 하는 일 | 끝나고 확인할 것 |
|---|---|
| 본문·소제목·출처·경험 슬롯 작성 | `## 출처` 앞에 본문이 모두 있는지 |
| AI가 명령 실행과 수정 반복 | 실패하면 제한 안에서 멈췄는지 |
| 기계 기준 점검 | 경고와 사실 확인 과제가 남아 있는지 |

CLI는 재작성을 자동 실행하지 않습니다. 이 반복은 AI가 관리합니다.
출처는 URL이 있는 줄 수를 셉니다. 링크 유효성과 주장 정확성은 별도로 확인합니다.
검사 통과는 사실·의료·법률 판단이나 게시 승인이 아닙니다.

## (e) 관문 기록

사람이 출처와 경험을 검토한 뒤 결정을 고릅니다. AI가 승인을 추정하면 안 됩니다.

| 결정 | 뜻 |
|---|---|
| `approved` | 사람이 승인함 |
| `edited` | 사람이 수정함 |
| `rejected` | 사람이 반려함 |
| `--missed-by-machine` | 기계가 놓친 문제를 사람이 발견함 |

승인한 경우에만 다음 예시를 실행합니다. 연습 로그는 따로 둡니다.

```powershell
uv run frame gate record --gate G2 --decision approved --run-id "연습-001" --note "출처와 경험을 직접 확인" --log logs/practice-gates.jsonl
uv run frame gate status --log logs/practice-gates.jsonl
```

```text
내가 검토한 관문 ID, 결정, 실행 번호, 메모, 기계 누락 여부를 받아 줘.
빠진 결정은 물어봐 줘. 내가 준 값으로 frame gate record를 실행해 줘.
연습 로그 logs/practice-gates.jsonl을 사용하고 같은 로그로 status를 보여 줘.
```

| 하는 일 | 끝나고 확인할 것 |
|---|---|
| 사람의 결정을 로그에 기록 | 관문·결정·실행 번호·로그 경로가 맞는지 |
| 현재 단계 확인 | G3·G5가 `HUMAN_ONLY`인지 |

기본 로그는 `logs/gates.jsonl`입니다. 메모에 실명·환자 정보·비밀을 쓰지 않습니다.
기록은 게시·업로드를 실행하지 않습니다. 최종 클릭은 항상 사람이 합니다.
