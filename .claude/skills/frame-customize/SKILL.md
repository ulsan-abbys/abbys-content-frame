# 분야 맞춤 설정

저장소 루트 기준으로 작업한다. 사용자에게는 한국어와 짧은 문장으로 설명한다.
[AI에게 맡기기](../../../docs/AI에게_맡기기.md)의 (b)를 따른다.

## (1) 현재 상태 확인

`README.md`, `AGENTS.md`, `config/profile.example.toml`, 기존 `config/profile.toml`을 읽는다.
`config/rules/`와 `src/frame/config_loader.py`에서 스키마를 확인한다.
기존 변경을 보존한다. 예시 프로필을 덮어쓰지 않는다.

## (2) 인터뷰

이미 받은 답은 재사용한다. 질문은 전체 최대 5개로 제한한다.

| 질문 | 설정에 반영할 내용 |
|---|---|
| 분야와 독자, 글의 목적은 무엇인가? | `persona.field`, `persona.purpose` |
| 화자 이름과 지역은 무엇인가? | `persona.name`, `persona.region` |
| 원하는 말투와 피할 표현은 무엇인가? | `style`과 규칙팩 |
| 글 분량·소제목·출처·경험 슬롯 기준은 무엇인가? | `draft` |
| 영상 길이와 첫 실습 주제는 무엇인가? | `video`와 예시 초안 |

미응답 항목은 예시 기본값 또는 확인 필요로 구분한다. 사용자 사실을 만들어 내지 않는다.

## (3) 프로필 작성

`config/profile.toml`을 작성하거나 기존 파일을 필요한 범위만 수정한다.
`persona`, `style`, `draft`, `rules`, `video`를 유지한다.
최소·최대 글자 수와 개수 기준, 경험 슬롯 정규식을 확인한다.
`persona`와 `style`은 초안 작성 때 직접 읽어 적용한다.
현재 `frame write`가 이 설정을 자동으로 프롬프트에 넣는다고 설명하지 않는다.

## (4) 규칙팩 초안

[새 모듈 만들기](../../../docs/새_모듈_만들기.md)의 규칙팩 스키마를 따른다.
`config/rules/<업종>_ko.toml`에서 `<업종>`은 `education` 같은 영문 식별자로 바꾼다.
팩 이름은 영문·숫자·밑줄·하이픈만 허용한다.
각 `[[rule]]`에 `id`, `pattern`, `severity`, `reason`, `ref`를 쓴다.
법 조항을 확인하지 못하면 `ref`에 `확인 필요`를 표시한다.
`rules.packs`에 확장자를 뺀 이름을 연결한다. 기존 업종 팩의 적합성도 검토한다.
허용·차단·오탐 사례를 남긴다. 규칙 변경의 경계 조건 테스트도 추가하거나 갱신한다.

## (5) 예시 초안 점검

`examples/`의 형식을 참고해 `drafts/01_내-주제.md`를 만든다.
본문 뒤에 `## 출처`를 둔다. 출처와 개인 경험을 지어내지 않는다.
사람의 경험은 프로필 정규식에 맞는 빈 슬롯으로 남긴다.
저장소 루트에서 `frame check drafts/01_내-주제.md`를 실행한다.
가상환경 활성화가 안 되면 `.\.venv\Scripts\python.exe -m frame check drafts/01_내-주제.md`를 쓴다.
초기 점검 후 수정은 최대 2회다. 매번 재점검하고 계속 실패하면 멈춘다.
통과를 위해 기준을 낮추거나 본문을 출처 아래로 옮기지 않는다.
실행 환경이 없으면 설치 절차를 따르고, 해결하지 못하면 실패 이유를 보고한다.

## (6) 검증과 보고

가상환경 Python이 있으면 그것으로 `python -m pytest -q`에 해당하는 명령을 실행한다.
변경 파일, 설정 전후, 명령과 종료 코드, 점검 결과, 미확인 근거를 표로 보고한다.
검사 통과는 사실·의료·법률 판단이나 게시 승인이 아님을 설명한다.
경험 슬롯과 관문 결정은 사람이 확인한다. G3·G5는 `HUMAN_ONLY`로 유지한다.
승인 없는 커밋·푸시를 하지 않는다. 게시·업로드 클릭은 사람이 한다.
