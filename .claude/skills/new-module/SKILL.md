# 새 모듈 추가

저장소 루트 기준으로 작업한다. 사용자 문구는 한국어로 작성한다.
[새 모듈 만들기](../../../docs/새_모듈_만들기.md)를 읽고 해당 확장 절차를 따른다.

| 순서 | 수행할 일 |
|---|---|
| (1) | `README.md`, `AGENTS.md`, 대상 설정·포트·모듈 카드와 기존 변경을 확인한다. |
| (2) | 입력·출력·끝 기준·실패 처리와 수정할 파일을 정한다. |
| (3) | 규칙팩·어댑터·노드 중 필요한 부분만 구현한다. |
| (4) | 정상 동작과 경계 조건 테스트를 추가하거나 갱신한다. |
| (5) | 모듈 카드·설정·README를 실제 구현 상태에 맞춘다. |
| (6) | PR 템플릿의 변경 이유·관련 모듈·검증 결과를 준비한다. |

규칙팩은 TOML의 `[[rule]]` 스키마를 따른다.
팩 이름은 영문·숫자·밑줄·하이픈만 사용하고 프로필에 연결한다.
확인하지 못한 법 조항은 `확인 필요`로 표시한다.

어댑터는 `core/ports.py`의 포트를 구현한다. 조립은 바깥에서 한다.
core가 adapters·cli를 import하거나 I/O를 수행하게 하지 않는다.
런타임은 Python 3.11 이상과 표준 라이브러리만 사용한다.
테스트는 가짜 구현과 가짜 응답을 쓴다. 실제 네트워크·외부 AI·영상 도구를 호출하지 않는다.

노드·관문을 추가하면 연결과 모듈 카드를 함께 갱신한다.
그래프는 설계 데이터이며 실행 엔진이 아님을 유지한다.
G3·G5의 `HUMAN_ONLY`와 N6 재작성 상한 2회를 보존한다.
새 관문 우회 경로, 중복 ID, 없는 연결 대상도 검사한다.

비밀·개인정보를 넣지 않는다. 승인 없이 커밋·푸시·원격 저장소 생성을 하지 않는다.
게시·업로드는 사람이 수행한다. PR은 템플릿으로 준비하고 사용자 승인 범위 안에서 진행한다.

마지막으로 저장소 루트에서 `python -m pytest -q`를 실행한다.
`.venv\Scripts\python.exe`가 있으면 `.\.venv\Scripts\python.exe -m pytest -q`를 사용한다.
아키텍처 검사를 우회하지 않는다. 실패 원인을 고치고 다시 검증한다.
변경 파일, 테스트 요약 줄, 미검증 항목, 남은 한계를 보고한다.
